1. Introduction and setup

This project examines two frozen pretrained models: a supervised Vision Transformer (ViT-B/16) trained on ImageNet-1k, and a contrastively trained vision-language model (CLIP ViT-B/32). No training or fine-tuning is performed anywhere in this work. Part 1 reconstructs the ViT input pipeline and evaluates its predictions on a self-collected image set. Part 2 reimplements the CLIP image-text similarity computation from first principles and verifies it against the library's own forward pass. Part 3 is a controlled study designed to test a specific hypothesis about what CLIP's similarity measures.

Patch projection

Each 16 × 16 × 3 patch holds 768 pixel values. These are multiplied by a learned matrix to produce a 768-dimensional token. torchvision implements this as a Conv2d whose kernel and stride both equal the patch size, which applies the same linear map to each non-overlapping patch - arithmetically identical to flatten-then-matmul, just a faster implementation.

Positional embeddings

Self-attention computes a weighted sum over tokens, so it is permutation-equivariant: permute the input patches and the outputs permute identically, carrying no information about where a patch came from. A learned position vector is therefore added to each token embedding, so the model can distinguish a top-left patch from a bottom-right one.

The CLS token

A single learned vector prepended to the sequence. It belongs to no patch and contains no image content of its own before attention runs; it accumulates information from every patch through self-attention, and the classification head reads only its final output. That is why the sequence length is 197 and not 196.

My visualisation versus the model's projection

My patchify only cuts the image into tiles so they can be displayed. The model's conv_proj additionally multiplies each tile by weights learned during ImageNet training, turning raw pixels into an embedding. Figure 1 therefore shows the input to that step, not its output.

Accuracy depends on the class-matching rule

ImageNet-1k contains several mutually exclusive classes for the same everyday object. Cats occupy at least five: tabby (281), tiger cat (282), Persian cat (283), Siamese cat (284), Egyptian cat (285). A photograph of an ordinary domestic cat can be assigned to any of them, and only "tabby" counts as correct under strict matching. The same holds for buses (school bus 779 versus minibus 654) and for drinking vessels (coffee mug 504, cup 968, espresso 967). So a prediction of "Egyptian cat" at probability 0.888 scores identically to "church" at 0.700, although one identifies the object correctly and the other does not.

To separate "the model misidentified the object" from "the model chose a sibling label", I define a second measure before counting. A prediction is object-correct if the predicted ImageNet class denotes the same everyday object as the category: any of the five cat classes for tabby_cat, any bus class for school_bus, any mug or cup class for coffee_mug, any guitar class for acoustic_guitar, any dog breed for golden_retriever.

MeasureValue
Strict top-1 (exact nominated index)15 / 30 = 0.500
Object-correct (any class denoting the same object)27 / 30 = 0.900
Right object, sibling label12 / 30 = 0.400

Only three predictions are genuine object errors: coffee_mug_05 → notebook, school_bus_01 → church, school_bus_06 → car wheel. Forty per cent of the apparent failures are the model naming a cat a different kind of cat, or a bus a different kind of bus.

Asked "does this model recognise these five categories", the figure to quote is 0.900, because the question is about objects and the rule was fixed before counting. The strict 0.500 answers a narrower question - whether the model selects one particular index out of several that denote the same thing - and that question is about the label set, not about recognition. Reporting either number alone would mislead; both are given, with the rule stated.

Two successes

acoustic_guitar_03.jpg, "acoustic guitar" at 0.956, the highest confidence in the collection. The photograph is a close-up of the headstock alone: six tuning machines, the nut, the strings converging, and the maker's name, against a wooden cabinet. Less than a fifth of the instrument is visible, yet confidence is higher than for any whole-guitar image in the set. The headstock has a distinctive and repeatable geometry, which suggests the class is carried by a characteristic part rather than by the overall silhouette.

golden_retriever_01.jpg, "golden retriever" at 0.911. A tight black-and-white portrait of the dog's face. The breed is named for its colour, and the colour has been removed, so the decision must rest on muzzle shape, ear set and fur texture. The top-5 is entirely other retrievers and large pale dogs, which is consistent with shape rather than colour driving the answer.

Two failures, and a third that is not the model's fault

acoustic_guitar_04.jpg → "electric guitar" at 0.160. An extreme close-up of the preamp and EQ panel set into the side of the guitar body: a black rectangular control plate with sliders, on glossy amber wood. There is no sound hole, no neck, no strings and no body outline anywhere in the frame. The visible evidence is electronics mounted in wood, and the model answered accordingly. This is also the lowest top-1 probability of all thirty images, with "acoustic guitar" second at 0.135 - the model is not confident, and its uncertainty is appropriate to how little of the instrument is shown.

golden_retriever_03.jpg → "clumber" at 0.514. A cream-coloured retriever standing in profile on grass in front of a red barn. Clumber spaniels are white, heavy-set and photographed in exactly this stance, and this dog's coat is pale enough to read as white. "golden retriever" is second at 0.159. The error is a sibling-breed confusion driven by an atypical coat colour for the category, not a failure to see a dog.

school_bus_01.jpg → "church" at 0.700. The frame is dominated by a church with a tall clock tower; the vehicle is a blue city coach, small, in the lower right corner. The model named the largest and most salient object in the picture, and it was right to. This is the mislabelled item identified in section 2: the prediction is a correct description of the photograph and an incorrect match to the label I assigned it.

A pattern connects three of these. In acoustic_guitar_04, school_bus_01 and coffee_mug_05 (→ "notebook" at 0.387, a black-and-white overhead shot of a laptop and a phone with the mug small at the right edge), the nominated object is present but is not the dominant object in the frame. A single top-1 label forces the model to choose one object per image, and it chooses the salient one. These failures are a property of the task definition at least as much as of the model.

The fixed-output limitation

This model can only ever answer with one of 1000 labels fixed at training time. It cannot be asked whether a person is riding or pushing a bicycle, whether a mug sits in grass or grass sits in a mug, or anything else expressed as free text. The question space is closed. That restriction is exactly what Part 2 removes, because CLIP's candidate set is whatever text is supplied at inference time.

5. Part 2 Task 1 - the CLIP similarity computation

Implemented in four steps from the image and text features rather than from the library's packaged output: L2-normalise both sets of features; take the matrix of dot products, which for unit vectors is the cosine similarity; multiply by the model's learned logit scale; apply a softmax along the candidate-text axis.

learned logit scale = exp(4.6052) = 100.000   →   tau = 1/100 = 0.01
max |my logits − open_clip's own forward pass| = 8.58e-06
zero-shot top-1 with "a photo of a {}" = 0.967  (29/30)

That difference is float32 rounding, not a discrepancy, so the reimplementation is confirmed correct.

Cosine, logit and probability are three different things

A cosine similarity is geometry: the angle between two unit vectors, bounded in [−1, 1], and a property of that one image-text pair alone. A logit is the same number multiplied by the learned scale of 100 - still per-pair, but stretched so a softmax can separate candidates that differ by hundredths of a cosine. A softmax probability is not a property of a pair at all: it is computed across a row, so it depends on every candidate text in the comparison.

Note how small the raw cosines are. The correct caption scores 0.3024 and the worst wrong one 0.1781 - a gap of about 0.12. After multiplication by 100 that becomes a gap of roughly 12 logits, which the softmax turns into 0.9999 versus 0.0000. The near-certainty in the last column is manufactured by the scale factor; it is not evidence that the model is certain.

Why the probabilities depend on the candidate set

For acoustic_guitar_04.jpg the five cosine similarities are 0.1973, 0.2044, 0.1922, 0.2313 and 0.2356 for golden retriever, tabby cat, coffee mug, acoustic guitar and school bus respectively.

A probability of 0.89 here does not mean the model recognises the guitar better; it means it was asked an easier question. This is why a softmax value cannot be quoted as a confidence in the model without also quoting the candidate set it was computed over.

The experiment therefore does not show that a bare label beats "a photo of a"; it shows that the three templates are indistinguishable at this sample size. Reporting the ranking as a finding would be reading noise as signal.

The image is the preamp close-up described in section 4. The cosine similarities explain why wording was enough to flip it: CLIP scores "acoustic guitar" at 0.2313 and "school bus" at 0.2356, a gap of 0.0043, roughly a twentieth of the 0.0878 mean margin CLIP achieves on the rest of the collection. When two candidates sit that close, a change to the template moves the text embeddings by more than the gap between them, and the argmax follows. All three probabilities are near 0.6 rather than the 0.9999 of a clean case, so the model itself signals the decision is marginal. The remaining twenty-nine images gave the same prediction under all three templates: the sensitivity is not general, it is concentrated in the one image where the evidence is weakest.

Why prompting is not fine-tuning

Every weight is frozen throughout. Changing the template changes only the text that gets encoded, which moves the text embeddings and therefore the similarity matrix. Fine-tuning would compute gradients and update the encoders; here no gradient is taken and nothing is stored. The same checkpoint gives different answers purely because it was asked a differently worded question.

Comparison with Part 1 - and why it is not a fair one

ViT scored 0.500 under strict matching (0.900 object-correct) and CLIP 0.967, but these are not comparable as "better" and "worse". ViT chooses among 1000 fixed classes, several of which are near-synonyms competing for the same photograph; CLIP chooses among the five texts I supplied, with no competing sibling labels at all. The two models also have different training objectives and training data, and CLIP has never been told these five categories exist. A like-for-like comparison would require giving both models the same candidate set.

Four of the five highest cross-category similarities involve the same image, which is a more specific observation than "dogs and cats are similar". Opening them answers why. golden_retriever_06.jpg is a puppy photographed head-on, its face and both front paws resting over a weathered wooden rail, the head filling most of the frame, in soft outdoor light. tabby_cat_04, _05 and _06 are head-and-shoulders portraits of the same cat resting on a stone step, face toward or across the camera, also filling the frame in soft outdoor light.

What the four closest pairs share is not species. It is a resting animal photographed close up and face-forward, the head occupying most of the frame, the body supported on a horizontal surface, soft fur against a neutral grey-brown background, and the same muted outdoor palette. The dog and the cats are photographed the same way.

The conclusion supported by these thirty images is that the image embedding carries pose, framing, scale and background alongside object identity, and that when two pictures agree on all of those, a difference of species is not enough to separate them cleanly. The within-category mean of 0.745 against an across-category mean of 0.515 shows category structure is present; the 0.766 between a puppy and a cat shows it is not the only thing present. This claim is scoped to this collection.

8. Part 3 - a controlled study of a CLIP limitation

This part reports two designs. The first asked whether CLIP distinguishes an action; it could not be executed reliably and is reported as a failed design together with the evidence that it failed. The second asks whether CLIP registers negation, and was built specifically to remove the weakness that defeated the first.

8.1 First design: riding versus pushing a bicycle

Hypothesis. CLIP's image-text similarity is driven mainly by which objects are present. If two captions name the same object and differ only in the action, matching should fall towards chance - 0.50 per image, 0.25 for a set in which both images are matched correctly.

Design. Ten matched sets, twenty images. Each set pairs a person riding a bicycle (A) with a person on foot with a bicycle (B), scored against "a person riding a bicycle" and "a person pushing a bicycle". Both captions name the bicycle, so recognising the object cannot resolve the choice; only the verb distinguishes them. Selection rules: both images show a bicycle clearly and at similar scale; the action must be unambiguous at a glance; unrelated properties (outdoor setting, one person, daylight, comparable viewpoint) kept as similar as practical.

Why it failed. The images were collected by keyword search against an openly licensed image repository. The search engine matches file titles and descriptions, which say what a picture is called, not what action it depicts. Four rounds of query revision and manual replacement did not fix this.

Changing the verb while holding the object fixed moves the embedding by 0.021. Changing the object while holding the verb fixed moves it by 0.073 - about three and a half times further. In this text encoder the noun dominates the verb. That observation motivated the second design.

8.2 Second design: does CLIP register negation?

Hypothesis. Negation reverses the meaning of a sentence while changing very few tokens. If CLIP's text encoder composes meaning, "a photo of a tabby cat" and "a photo of no tabby cat" should sit far apart, and an image containing a cat should prefer the first by a wide margin. If the embedding is instead dominated by which nouns appear, the two captions will be close and the image will barely separate them.

Design. The thirty images already collected, licensed and visually checked for Parts 1 and 2. Each image is scored against the caption pair for its own category, so every comparison differs by exactly one word. Nothing new was downloaded, and the content of every image was already established. The quantity being varied lives in the text, where it is under exact control - which is precisely what the first design lacked.

Baseline for scale. Part 2 measured how far CLIP separates the correct object from the best competing object on these same images: mean margin 0.0878. That is the model working well, in the same units.

The honest reading is two-sided, and both sides matter. CLIP is not blind to negation: 24 of 30 is significantly above chance (p = 0.0014), so adding "no" does shift the embedding in the right direction. But the shift is nine times smaller than the shift the model uses to tell a cat from a bus. A word that reverses the truth of a sentence moves the representation about a ninth as far as swapping one object noun for another. That is the finding: not an absence of sensitivity, but a gross mismatch of scale between logical content and object content.

Four of the six failures are golden retrievers. That category alone scores 2/6 with a mean margin of −0.0004, while tabby cat and school bus score 6/6. The images confirm why. golden_retriever_02.jpg shows a golden retriever and a beagle standing together on grass, the beagle in a harness in the foreground. golden_retriever_04.jpg is a close-up of a beagle and a golden retriever side by side indoors, both faces filling the frame. golden_retriever_05.jpg shows the two dogs from behind on grass, and here the retriever is pale, turned away and no larger than the beagle. Five of the six were also misclassified by ViT in Part 1, independently of CLIP and with a different training objective. Across all thirty images the correlation between cos(positive) and the margin is +0.64. The more strongly an image matches its caption, the more the negation is penalised. So the six failures are not a random subset: they are the images that are weak instances of their own label. Negation is penalised in proportion to how strongly the image supports the positive caption, which is what one would expect if "no X" is being treated as a slightly weaker statement about X rather than as a denial of it.

Task 3: one controlled change

One variable changed: the phrasing of the negation, from "a photo of no X" to "a photo with no X in it". Same images, same model, same computation.

Three images changed answer, all three in the same direction, and no image was lost. McNemar's exact two-sided test on those three discordant images gives p = 0.25, so the count change is not significant at this sample size. The margin change is the more interesting number: the mean margin nearly trebled, which is a change in how strongly the model separates the two captions rather than merely which one wins. Even so, 0.0284 remains about a third of the 0.0878 object margin.

Alternative explanations: a wording effect speaks to the text encoder "with no X in it" is longer and more explicitly spatial, so it may differ from the positive caption in ways beyond the negation alone and with thirty images one image is worth 0.033 of the count, so only the margin change is comfortably outside noise.

Limits

  • Five categories and thirty images. Category-level effects, such as the golden retriever result, rest on six images each.
  • Every image contains its object. The study never presents an image that genuinely lacks the object, so it measures whether negation is penalised.
  • Only two negation templates were tried. Other phrasings may behave differently - the one variant tested nearly trebled the margin, which already shows phrasing matters.
  • The effect is located in the text encoder. Nothing here shows the image encoder is at fault, and nothing here shows CLIP is unfit for the retrieval tasks it was built for.

Conclusion

On these thirty images CLIP registers negation but at the wrong order of magnitude. The positive caption is preferred in 24 of 30 cases, so the word "no" is not simply discarded, yet the mean separation it produces is about one ninth of the separation the same model uses to distinguish one object from another on the same images. The text-only measurements locate the cause: a caption and its own denial are nearly parallel vectors, so the image is choosing between two statements the encoder considers almost the same.

What would make this wrong. If the effect disappeared under a wider range of negation phrasings, the finding would be about two particular templates rather than about negation. If images genuinely lacking the object preferred the negated caption by a comparable margin, the model would be representing absence after all and this design would simply be insensitive to it. If the six failures turned out to be distributed at random rather than concentrated in weak instances, the proportionality argument would fail. And with five categories and thirty images a different collection could move the 24/30 appreciably, though it would have to move a long way to close a ninefold gap in scale.

9. What I would do differently

Fix the evaluation rule before measuring, not after. Part 1's accuracy moved from 0.500 to 0.900 purely by stating which predicted classes count as the same object. I discovered the sibling-class problem by inspecting failures after the fact. The rule should have been written down with the category list, before any model was run.

Validate test items against the label, not against the search query. The first Part 3 design failed because images were collected by keyword, and the keyword describes what a file is called. Four collection attempts produced accuracies that measured item quality. A visual audit of all twenty items should have been the first step after the first download.

Prefer designs where the manipulated variable is under exact control. The second design varied one word of text on images whose contents were already established, and produced an interpretable result on the first run. The difference between the two designs is not subject matter.

Size the sample against the effect being looked for. With twenty images one flipped item is worth 0.05 of accuracy, so the Part 3 wording comparison could not have detected anything smaller than its own noise floor.

Record data problems rather than removing them. school_bus_01 is mislabelled and is kept, because dropping an item after seeing its score selects data on the outcome.
